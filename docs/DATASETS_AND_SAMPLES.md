# Dataset Specifications, Schemas & Canonical Samples

This document provides complete reference specifications, schemas, statistical contracts, and canonical annotated samples for all datasets generated by **nanoGentzen Studio**.

Before running exports, working records are persisted in a local SQLite database (`clearcot.db`). When exporting from the Studio UI or CLI, datasets are partitioned and formatted for specific fine-tuning, preference alignment, and evaluation workflows.

---

## 📑 Dataset Catalog Overview

| Dataset File | Format | Target Workflow | Key Properties |
|---|---|---|---|
| **`clearcot_sft_dataset.jsonl`** | JSON Lines | Supervised Fine-Tuning (SFT) | Standard `conversations` format with lean `<think>` blocks and comprehensive `<answer>` blocks. |
| **`clearcot_dpo_pairs.jsonl`** | JSON Lines | Direct Preference Optimization (DPO) | Contrastive pairs: `chosen` (lean, load-bearing deduction) vs. `rejected` (verbose, ungrounded conversational rambling). |
| **`clearcot_dataset.parquet`** | Apache Parquet | High-Performance SFT / Analysis | Dense columnar storage, verified proof statuses, Curry-Howard terms, clarity scores, zero-null contract. |
| **`jev_decisions_dataset.jsonl`** | JSON Lines | Structured Decision Reasoning | State dictionary, multi-hop relational path, policy rules, criteria, Gold determination, Curry-Howard proof term. |
| **`typed_decisions_dataset.parquet`** | Apache Parquet | Tabular Decision Evaluation | Positional 13-column schema with question-level breakdown, probability vectors, and verification status. |
| **`open_jev_s1mb_dataset.parquet`** | Apache Parquet | System 1 Model Benchmark | Standardized Open-Jev format (`case_id`, `input`, `targets`, `language`, `input_hash`). |

## 💎 The ClearCoT Standard: Occam Reasoning & Zero Citation Noise

All ClearCoT datasets strictly adhere to the **Question – Reasoning – Answer (Q–R–A)** standard grounded in **nanoGentzen-v4**:

1. **Occam `<think>` Trace**:
   - Every sentence is a load-bearing deduction step.
   - Conversational filler ("Hmm, let me think", "Wait, maybe that's not right") is entirely eliminated.
   - fewer reasoning tokens than the same model's step-by-step answer, measured per sample (`tokens_saved_pct`).
2. **Direct Semantic Grounding**:
   - Arguments focus on concepts and author claims directly (e.g., *"Doerig argues that consciousness requires..."* instead of bibliographical markers like *"Doerig et al. is..."*).
3. **Formal Constructive Verification**:
   - Each reasoning trace is paired with an intuitionistic logic sequent $\Gamma \vdash \Delta$ evaluated by Dyckhoff's $G4ip$ decision procedure.
   - Proven sequents include a verified typed $\lambda$-calculus Curry-Howard proof term (`curry_howard_term`).
   - Saul Kripke model checking provides epistemic status (`PROVEN_TRUE`, `PROVEN_FALSE`, `INTUITIONISTIC_UNDECIDED`, `INCONSISTENT_PREMISES`).

## 5. Positional Typed Decisions Parquet (`typed_decisions_dataset.parquet`)

### Parquet Schema Contract (13 Positional Columns)

```
Schema:
 0: id                 string
 1: workflow           string
 2: split              string
 3: state              string (JSON string of state dictionary)
 4: questions          string (JSON string of questions dictionary)
 5: gold               string (JSON string of gold determination and certificate)
 6: factors            string (JSON string of influential factors)
 7: n_questions        int64 (number of decisions in scenario)
 8: q1__id             string (e.g. "determination")
 9: q1__label          string (e.g. "compatible", "incompatible", "undecided")
10: q1__confidence     double
11: q1__probabilities  string (JSON string of normalized probability distribution)
12: q1__verification   string (e.g. "PROVEN_TRUE", "NO_OPTION_PROVABLE")
```

## 6. Open-Jev System 1 Benchmark Parquet (`open_jev_s1mb_dataset.parquet`)

Standardized benchmark format for evaluating System 1 sub-5ms heuristic decisions against exact Dyckhoff proofs.

### Schema Contract

```
Schema:
 0: case_id     string (e.g. "scientific_theories:JEV-A9B62B")
 1: group_id    string (grouped case cluster identifier)
 2: split       string ("train", "val", "test")
 3: language    string ("en")
 4: input_hash  string (SHA-256 of canonical input JSON)
 5: input       struct<state_json: string>
 6: targets     list<element: struct<annotation_kind: string, decision_id: string, ids: list<string>, kind: string, label: string, probabilities: list<double>>>
```

## 7. SQLite Working Database Schema (`data/clearcot.db`)

When executing batch runs inside the Studio, results are recorded in `data/clearcot.db` prior to file export.

### DDL Schema

```sql
CREATE TABLE IF NOT EXISTS samples (
    sample_id TEXT PRIMARY KEY,
    doc_name TEXT NOT NULL,
    question TEXT NOT NULL,
    reasoning TEXT NOT NULL,
    answer TEXT NOT NULL,
    naive_cot TEXT DEFAULT '',
    status TEXT DEFAULT 'draft',
    gentzen_verified INTEGER DEFAULT 0,
    gentzen_sequent TEXT DEFAULT '',
    proof_tree_json TEXT DEFAULT '{}',
    provability_score REAL DEFAULT 0.0,
    tokens_saved_pct INTEGER DEFAULT 0,
    clarity_score REAL DEFAULT 0.0,
    provenance_json TEXT DEFAULT '{}',
    created_at TEXT NOT NULL,
    curry_howard_term TEXT DEFAULT '',
    epistemic_status TEXT DEFAULT 'UNDECIDED',
    grounding_score REAL DEFAULT 0.0
);

CREATE TABLE IF NOT EXISTS jev_samples (
    sample_id TEXT PRIMARY KEY,
    doc_name TEXT NOT NULL,
    workflow TEXT NOT NULL,
    split TEXT NOT NULL DEFAULT 'train',
    state_json TEXT NOT NULL,
    questions_json TEXT NOT NULL,
    gold_json TEXT NOT NULL,
    factors_json TEXT NOT NULL,
    policy_rules_json TEXT NOT NULL,
    target_decision TEXT NOT NULL,
    gentzen_verified INTEGER DEFAULT 0,
    gentzen_sequent TEXT DEFAULT '',
    curry_howard_term TEXT DEFAULT '',
    epistemic_status TEXT DEFAULT 'UNDECIDED',
    status TEXT DEFAULT 'draft',
    provenance_json TEXT DEFAULT '{}',
    created_at TEXT NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_samples_status ON samples(status);
CREATE INDEX IF NOT EXISTS idx_samples_verified ON samples(gentzen_verified);
CREATE INDEX IF NOT EXISTS idx_jev_workflow ON jev_samples(workflow);
CREATE INDEX IF NOT EXISTS idx_jev_status ON jev_samples(status);
```

## 8. Generating and Exporting Datasets

To produce new dataset exports from source documents:

1. **Launch the Studio**:
   ```bash
   streamlit run app.py
   ```
2. **Batch Generation**:
   - Navigate to the **"Complete Jev Batch Generator"** tab.
   - Upload PDF or text source documents (or use existing parsed documents).
   - Set the desired number of paths and records (e.g. 50 to 500).
   - Select your LLM provider or offline heuristic generator.
   - Click **Run Complete Jev Batch Generator**.
3. **Export Datasets**:
   - Navigate to the **Export** tab or click **Export All Datasets**.
   - Datasets will be populated in `data/exports/` in JSONL and Parquet formats.
   - All files are verified with zero null values and valid split partitions (`train`, `val`, `test`).
